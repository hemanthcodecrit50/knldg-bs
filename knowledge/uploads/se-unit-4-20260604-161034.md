# Agile Software Development Study Notes

## What is Agile Software Development?
- **Definition of Agile:** 
  - Agile refers to software processes that are easily moved, light, nimble, and active.
- **How is agility achieved?**
  - Fitting the process to the project.
  - Avoiding time-wasting practices.

## Agile Model
- **Purpose:** 
  - Developed to address the shortcomings of the waterfall model.
  - Aimed to help projects adapt to change requests.
- **Requirements Management:** 
  - Decomposes requirements into small incremental parts developed over 1-4 weeks.

## Ideology: Agile Manifesto
- **Core Values:**
  - Individuals and interactions **over** processes and tools.
  - Working software **over** comprehensive documentation.
  - Customer collaboration **over** contract negotiation.
  - Responding to change **over** following a plan.
  
  Source: [Agile Manifesto](http://www.agilemanifesto.org)

## Agile Methodologies
Some popular Agile methodologies include:
- **Scrum**
- **Extreme Programming (XP)**
- **Lean**
- **Kanban**
- **Crystal**
- **Dynamic Systems Development Method (DSDM)**

## Principal Techniques in the Agile Model
- **User Stories:** 
  - Requirements are expressed as user stories for better understanding.
- **Metaphors:** 
  - Use common vision based on user stories.
- **Spikes:** 
  - Simple programs created to explore potential solutions.
- **Refactoring:** 
  - Restructure existing code without changing its functionality.

## Agile Model Characteristics
- **Incremental Releases:** 
  - Software is released in iterations; functionalities can vary in each.
- **Documentation Requirements:** 
  - Concise, accurate, and relevant documentation. Documentation is less than traditional models.
- **Face-to-Face Communication:** 
  - Encouraged to promote effective collaboration.

## Agile Principles
- **Primary Measure of Progress:** 
  - Incremental release of working software.
- **Core Principles:**
  - Frequent delivery (every few weeks).
  - Adaptable to changes.
  - Close cooperation between customers and teams.
  - Emphasis on face-to-face communication.

## Agile Documentation
- Agreed that too much documentation is unnecessary.
- Important documentation serves the following purposes:
  - Stakeholders require it.
  - Defines contracts.
  - Supports communication externally.
  - Encourages clarity of thoughts.

## Agile Software Requirements Management
- Prioritize and manage requirements per iteration.
- High-priority requirements are addressed first.
- Requirements can be reprioritized and removed as needed.

## Challenges of Agile Approaches
- Possible inconsistencies in definitions.
- Requires high-quality interpersonal skills.
- Short iterations may restrict long-term perspectives.
- Risk of feature creep affecting scope and expectations.

## Agile Model vs. Waterfall Model
- **Waterfall Model:**
  - Follows a sequential phase-based approach.
  - Progress measured by artifacts.
  
- **Agile Model:**
  - Sequences development into incremental releases rather than phases.
  - Emphasizes flexibility and accommodating changes.

## Extreme Programming (XP)
- Developed by Kent Beck in 1999.
- **Core Practices:** 
  - Focus on customer requirements and rapid iterations.
  - Encourages practices like pair programming and test-driven development.
  - Values simplicity, frequent feedback, and communication.
  
## Scrum Framework
- **Roles:**
  - **Product Owner:** Represents customer interests; prioritizes features.
  - **Scrum Master:** Facilitates the process and removes obstacles.
  - **Development Team:** Cross-functional, self-organizing team.
  
- **Ceremonies:**
  - **Sprint Planning:** Determine what to accomplish.
  - **Daily Scrum:** Short meeting for progress updates.
  - **Sprint Review:** Demonstration of completed work.
  
- **Artifacts:**
  - **Product Backlog:** Prioritized list of all work.
  - **Sprint Backlog:** Work defined for the current sprint.
  - **Burndown Chart:** Visualizes work completed vs. remaining.

## User Stories
- Write user stories to define features from customers’ perspectives.
- Follow the "INVEST" criteria: Independent, Negotiable, Valuable, Estimable, Small, Testable.
